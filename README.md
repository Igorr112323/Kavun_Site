# Vip-service — сайт и админка

Продажа, ремонт, обслуживание и перевозка промышленного оборудования для алюминиевых и пластиковых конструкций.
Краснодар, ст. Старокорсунская, ул. Полевая, 43.

Репозиторий содержит полностью рабочий сайт: публичную часть с каталогом, сервисные страницы,
PDF-каталоги, формы заявок и админ-панель, из которой заказчик сам управляет оборудованием,
новостями, текстами и заявками.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · SQLite (better-sqlite3) · собственный CSS.
Без Tailwind, без тяжёлых motion-библиотек, без внешних CMS и CDN.

## Быстрый старт

Нужен **Node.js 20.9+** (проверено на 22.22): https://nodejs.org — берите LTS.
Дальше выберите свою систему.

### Windows

**Скачивание.** Если файл из чата не появился в `Downloads`, скачайте архив напрямую из GitHub —
это надёжнее и не зависит от браузера:

```powershell
cd $HOME\Downloads
Invoke-WebRequest -Uri "https://codeload.github.com/Igorr112323/Kavun_Site/zip/refs/heads/arena/037ca4fa-kavun-site" -OutFile "vip-service.zip"
Expand-Archive -Path .\vip-service.zip -DestinationPath . -Force
Rename-Item -Path .\Kavun_Site-arena-037ca4fa-kavun-site -NewName vip-service
cd .\vip-service
```

Или через git (если он установлен):

```powershell
cd $HOME
git clone -b arena/037ca4fa-kavun-site https://github.com/Igorr112323/Kavun_Site.git vip-service
cd .\vip-service
```

**Запуск.** Самый простой путь — запустить **`start-windows.cmd`** (двойной клик).
Скрипт сам проверит Node, создаст `.env`, поставит зависимости, соберёт сайт,
запустит сервер в отдельном окне и откроет браузер. Повторный запуск — быстрее,
сборка пропускается.

Вручную, в PowerShell (не в cmd):

```powershell
# распаковать архив (в PowerShell нет команды unzip)
Expand-Archive -Path .\vip-service.zip -DestinationPath .

cd vip-service
Copy-Item .env.example .env
npm ci
npm run build
npm start
```

Порт занят — `npm start -- -p 3001`.

Если PowerShell пишет «выполнение сценариев отключено» (это про `npm.ps1`):

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Тогда же помогает запуск через `npm.cmd ci` вместо `npm ci`.

Если `npm ci` падает на `better-sqlite3` с ошибкой сборки — поставьте Node.js LTS 22,
либо «Visual Studio Build Tools» с компонентом «Desktop development with C++».

### macOS / Linux

```bash
# для better-sqlite3 нужны python3, make, g++
npm ci

cp .env.example .env
# DATABASE_PATH=./data/vip-service.db
# SITE_URL=https://ваш-домен.ру

npm run build
npm start                      # http://localhost:3000
```

База создаётся и наполняется демо-данными при первом открытии любой страницы
(идемпотентно: если пользователи уже есть, наполнение не повторяется).

**Доступы в админку** (`/login`) — создаются при первом запуске:

| Роль | Почта | Пароль | Права |
|---|---|---|---|
| Администратор | `admin@vip-service23.ru` | `VipService2026!` | всё, включая пользователей и настройки |
| Контент-менеджер | `editor@vip-service23.ru` | `Redaktor2026!` | оборудование, новости, категории, каталоги, страницы, заявки |

> Пароли видны в исходниках — **смените их сразу после установки** в разделе «Пользователи»,
> а тестового редактора удалите, если он не нужен.

Полезные команды:

```bash
npm run typecheck   # tsc --noEmit
npm run assets      # пересобрать обложки каталогов и OG-изображения (python3 + sharp)
npm run pdf         # пересобрать демо-PDF каталогов и паспортов
```

Полный сброс демо-базы (удалит все правки): остановить сервер, удалить `data/vip-service.db*`,
запустить снова и открыть сайт.

## 1. Анализ конкурентов

Смотрели публичные русскоязычные версии сайтов производителей (октябрь 2026), а не только
английские: наш клиент читает по-русски и ищет станок под конкретную номенклатуру.

| Сайт | Что хорошо | Что слабо для российского покупателя | Что берём | Что делаем иначе |
|---|---|---|---|---|
| **elumatec** | Репутация и полнота линейки: SBZ, DG, прессовый инструмент. Аккуратная корпоративная подача, локализованные страницы, сервисная сеть. | Каталог живёт в PDF и в «семействах» моделей: чтобы сравнить SBZ 122 и SBZ 140, нужно открыть два документа и держать цифры в голове. Цен, наличия и сроков нет — только «свяжитесь с нами». Форма без обещания срока ответа. | Немецкую точность подачи характеристик, структуру «семейство → модель → опции». | Показываем цену или честное «по запросу», статус склада и срок. Характеристики — таблицей на карточке, а не в PDF. |
| **Emmegi** | Сильные продуктовые страницы портальных центров, хорошие рендеры и спецификации, понятная навигация по типам станков. | Маркетинг преобладает над ответом «сколько стоит и когда будет». Ни б/у, ни перевозки, ни сервиса в России. Русские страницы местами — перевод с итальянского. | Подачу сложной техники (портальные центры, длинные ходы) через конкретные цифры и сценарии применения. | Добавляем второй контур — б/у станки с проверкой и логистику. Это то, что покупатель всё равно спрашивает по телефону. |
| **Stürtz** | Глубокая экспертиза в ПВХ: сварка, зачистка угла, автоматизация участка. Чистая немецкая типографика. | Узкая специализация: про алюминий и перевозку здесь ничего не найдётся. Много PDF, мало «живых» ответов на вопросы цеха. | Специализацию: у нас тоже есть узкие компетенции — сервис и б/у, а не «всё для всех». | Пишем как инженеры: типовые неисправности, сроки диагностики, что проверяем перед продажей б/у. |
| **Haffner** | Широкая линейка для ПВХ, узнаваемая продуктовая матрица, международная дилерская сеть. | Русская версия фрагментарна; про наличие в РФ и запчасти — общие слова. Нет прозрачной цены и состояния б/у. | Продуктовую матрицу и спокойный визуальный тон. | Даём местную фактуру: склад в Краснодаре, выезд по ЮФО, сроки в часах, а не «в кратчайшие сроки». |

**Что это значит для Vip-service.** Крупные производители выигрывают брендом и глубиной каталога,
но проигрывают в трёх вещах, которые решают сделку у небольшого цеха: **наличие, состояние б/у и сервис
на месте**. Ни один из четырёх сайтов не отвечает на вопрос «что стоит на складе в Краснодаре сегодня
и что с ним делали». Поэтому сайт строится не как «витрина бренда», а как **склад и сервисная служба
с каталогом**.

## 2. Десять решений, которые выделяют сайт

1. **Реальное наличие вместо размытого «под заказ».** В первом экране — счётчик единиц, которые
   физически стоят на складе (8 из 12 позиций), отдельно сказано, что ещё 4 в пути и под заказ.
   Счётчик считается из базы по статусу `in_stock`, а не вписан руками.
2. **Б/у как инженерный документ, а не лотерея.** Девять пунктов проверки, замер геометрии после
   40–60 минут прогрева, биение шпинделя, тестовая деталь на профиле клиента. На фото — штамп
   «Проверено · запущено · октябрь 2026 · механик».
3. **Цены там, где их можно назвать.** Новый Comet R4 — 9 870 000 ₽ с НДС; б/у SBZ 140 — 4 350 000 ₽;
   где цена зависит от комплектации — «по запросу» с обещанием ответа за 2 часа, а не пустое место.
4. **Сервис с цифрами.** Диагностика 2 500 ₽ (входит в ремонт), выезд по Краснодару 24 часа,
   по ЮФО до 48, гарантия на работы 3 месяца. Это проверяемые обещания, а не «оперативно».
5. **Логистика как отдельная компетенция.** Негабарит до 13 м, расчёт маршрута до выезда (ворота,
   повороты, высота проёма, нагрузка на пол), страхование 100 %, кейс перевозки Satellite XTE 10,5 м
   из Подмосковья за 9 дней.
6. **Каталоги без регистрации.** PDF открываются сразу. Честно подписаны как выдержки: полную версию
   на 180 страниц присылаем по запросу — так и продажа, и никакой лжи в интерфейсе.
7. **Сравнение станков до трёх позиций.** Не «добавить в избранное», а таблица характеристик рядом:
   ходы, шпиндель, поворот оси, цена. Работает на клиенте, не требует регистрации.
8. **Схема проезда вместо тяжёлой карты.** Собственная SVG-схема с М-4 и Полевой, 43 + ссылка
   «Открыть в Яндекс.Картах». Карта не грузит 300 КБ скриптов и не ломает первый экран.
9. **Админка, в которой разберётся не-программист.** Крупные поля, загрузка фото drag&drop,
   публикация в один клик, заявки со статусами и выгрузкой в CSV, роли «администратор» и «редактор».
10. **Техническая эстетика вместо «премиум-градиентов».** Графит, бумага, сигнальный оранжевый,
    моноширинные цифры, чертёжные засечки, Oswald + Onest + IBM Plex Mono. Ни одного стокового
    «менеджера с планшетом».

## 3. Айдентика

### 3.1. Логотип — два варианта

Знак строится на поперечном сечении алюминиевого профиля: квадрат заготовки, внутренняя камера,
осевая линия реза и оранжевая риска допуска. Никаких шестерёнок и буквы V в круге.

**Вариант A — «Профиль» (по умолчанию, `logo_variant: profile`)**
Квадрат 32×32 с внутренним контуром камеры, вертикальная ось проходит через верх и низ,
справа — оранжевый угловой вырез. Читается как чертёж детали и как буква «П» — профиль.
В монохроме работает целиком; в акценте — только вырез (одна смысловая деталь, не «покрасим всё в оранжевый»).

**Вариант B — «Паз» (`logo_variant: groove`)**
Рамка с горизонтальными линиями-допусками, сверху — V-образный паз (след фрезы), внизу — оранжевая
точка-фиксатор. Более «механический» характер, лучше смотрится на маленьких размерах в аватарках.

Оба варианта живут в `components/logo.tsx`, переключаются в админке: **Настройки → Вариант логотипа**.
Иконка сайта — `app/icon.svg`, фавикон наследует вариант A.

### 3.3. Типографика

| Роль | Шрифт | Размеры | Зачем |
|---|---|---|---|
| Заголовки | **Oswald** (variable, self-hosted) | H1 `clamp(2.55rem, 6.4vw, 6.1rem)`, H2 `clamp(1.9rem, 3.7vw, 3.15rem)`, H3 `clamp(1.25rem, 1.8vw, 1.55rem)`, line-height 0.98, uppercase | Узкий индустриальный гротеск: даёт «плакатность» и экономит ширину на длинных русских словах |
| Текст | **Onest** (variable) | 17px / 1.62, вторичный 13–15px | Нейтральный, хорошо читаемый кириллический гротеск; не Inter, чтобы не выглядеть «как все» |
| Технические подписи | **IBM Plex Mono** | 9,5–11px, uppercase, letter-spacing 0.08–0.13em | Артикулы, даты, единицы, статусы, подписи к фото — «бирка на станке» |

Шрифты лежат в npm-пакетах `@fontsource` и отдаются с нашего домена: **ни одного запроса к Google Fonts**,
никаких «мигающих» подмен и лишних 300 мс на первом экране. Цифры в характеристиках — табличные
(`font-variant-numeric: tabular-nums`), чтобы колонки не плясали.

### 3.4. Сетка и ритм

- Контейнер: **1400 px**, боковые поля `clamp(18px, 4.2vw, 56px)`.
- Вертикальный ритм секций: `clamp(64px, 8.5vw, 128px)` — на мобильном плотнее, на десктопе воздух.
- Модульная сетка: 2 колонки в hero (текст 54 % / фото 46 %), 3 карточки в каталоге, 4 факта в строке;
  все сетки на `minmax(0, 1fr)`, чтобы длинные названия не распирали колонки.
- Радиусы: 2 px и 4 px. Скругления «как в мобильном приложении» сознательно не используются.
- Границы вместо теней: 1 px `--line`, тени только на hover карточек.
- Шапка 74 px, sticky, при скролле — полупрозрачный графит с blur.

### 3.5. Визуальные акценты

1. **Чертёжная разметка**: тонкие линии, угловые засечки `corner--tl/br` на фото, координатная подпись
   «Склад · Краснодар · 20.10.2026».
2. **Плашка-бирка** на первом экране: номер единицы, дата, статус — как ярлык на стеллаже.
3. **Штамп проверки** на фото б/у: повёрнутая рамка с датой и подписью механика.
4. **Нумерация блоков** 01–08 моноширинным шрифтом: задаёт порядок чтения и «каталог» вместо «лендинга».
5. **Крупные цифры-факты** (740 станков, 48 часов, 9 пунктов, 3 месяца) — не иконки, а числа.
6. **Фотографии цеха и деталей**: шпиндель, диск пилы, склад, погрузка. Люди — только в процессе работы,
   без постановочных улыбок.

## 4. Motion-спецификация

Принцип: анимация объясняет появление, а не развлекает. Всё на `transform` и `opacity`,
кроме одного одноразового `clip-path` на первом экране. Ни одной библиотеки — CSS + IntersectionObserver
(≈1,5 КБ кода вместо 40–60 КБ Framer Motion/GSAP). Lenis не используется: нативный скролл предсказуемее,
а «инерция» ломает ощущение скорости на длинных каталогах.

| Эффект | Где | Параметры | Easing |
|---|---|---|---|
| Появление первого экрана | hero: надзаголовок, строки H1, лид, кнопки | `riseIn` 0,9 s, задержки 0,08 / 0,18 / 0,28 / 0,36 / 0,44 s, сдвиг 22 px | `cubic-bezier(.16,1,.3,1)` |
| Медиа первого экрана | фото справа | `mediaIn` 1,15 s: `clip-path` снизу + opacity, задержка 0,16 s | тот же |
| Зум фото | hero-изображение | `scale(1.06) → 1`, 1,6 s | тот же |
| Reveal блоков | все секции | opacity 0→1, `translateY(26px)→0`, 0,65 s, задержка по индексу 60–80 ms | тот же |
| Счётчики | 12/740/48/3 | 1 200 ms, ease-out cubic, старт при 40 % видимости | JS rAF |
| Hover карточки | каталог | `translateY(-4px)`, рамка `rgba(255,77,18,.55)`, тень, зум фото 1,04 | 0,3–0,5 s |
| Кнопка-стрелка | все CTA | сдвиг стрелки на 4 px + подсветка | 0,25 s |
| Подчёркивание в меню | навигация | `scaleX(0)→1` от левого края | 0,35 s |
| Мега-меню | «Оборудование» | fade + сдвиг 8 px, пункты stagger 40 ms | 0,2–0,3 s |
| Мобильное меню | бургер | панель выезжает, пункты stagger, focus-trap, Esc | 0,3 s |
| Фильтры каталога | чипы/селекты | перестройка сетки через `router.replace` + `useTransition`, без layout-дёрганья | CSS transition 0,25 s |

**Производительность и доступность**

- Анимируются только `transform` и `opacity`; `width/top/margin` не трогаем.
- `will-change` — только на `.reveal` (снимается после появления).
- Параллакса нет вовсе: на мобильных он превращается в дёрганье, а на десктопе не добавляет смысла.
- `@media (prefers-reduced-motion: reduce)` отключает входные анимации, reveal показывается сразу,
  `scroll-behavior` становится `auto`. Проверено на всех уровнях: глобальный CSS + JS-компоненты.

## 8. Модель данных

SQLite, 10 таблиц. Схема — `lib/schema.ts`, создаётся идемпотентно (`CREATE TABLE IF NOT EXISTS`).

```
users ──< sessions
categories ──< equipment >── manufacturers
posts ──> equipment            (новость может ссылаться на карточку)
catalogs ──> manufacturers
requests ──> equipment         (заявка помнит, с какой карточки пришла)
pages                          (редактируемые тексты, slug = ключ)
settings                       (key/value: телефон, адрес, статистика, логотип)
```

| Таблица | Поля (кратко) |
|---|---|
| `users` | id, email (unique), password_hash (scrypt), name, role (`admin`/`editor`), is_active, created_at |
| `sessions` | token (PK), user_id → users, expires_at, created_at |
| `categories` | id, slug (unique), title, short_title, description, sort |
| `manufacturers` | id, slug, name, country, founded, site_url, summary, note, sort |
| `equipment` | id, slug, title, manufacturer_id, category_id, model, condition (`new`/`used`), year, price, price_on_request, status (`in_stock`/`in_transit`/`on_order`/`reserved`/`sold`), specs (JSON `[{label,value}]`), description, condition_note, checked, complete_set, power, weight, dimensions, images (JSON массив), passport_url, is_published, is_featured, sort, created_at, updated_at |
| `posts` | id, slug, title, excerpt, body, cover, equipment_id, published_at, is_published, is_pinned |
| `catalogs` | id, title, manufacturer_id, description, cover, pdf_url, pages_label, file_size, year, sort |
| `requests` | id, name, phone, email, message, equipment_id, source_page, status (`new`/`in_progress`/`closed`), manager_note, created_at |
| `pages` | slug (PK), title, seo_title, seo_description, blocks (JSON), updated_at |
| `settings` | key (PK), value |

Связи: `equipment.manufacturer_id → manufacturers.id` и `equipment.category_id → categories.id`
(`ON DELETE SET NULL` — удаление категории не убивает карточки), `requests.equipment_id → equipment.id`,
`posts.equipment_id → equipment.id`.

Индексы: `(condition, is_published)`, `slug`, `requests.created_at`.

## 9. Админ-панель

`/admin` — тёмная минималистичная панель на русском, без визуального конструктора.

| Раздел | Что делает |
|---|---|
| **Сводка** | Счётчики: оборудование, новости, новые заявки; быстрые действия |
| **Оборудование** | Список с поиском, публикация в один клик, удаление с подтверждением. Форма: название, slug (авто), производитель, категория, модель, состояние, год, цена / «по запросу», статус наличия, характеристики (динамические строки), описание, состояние и комплектация, мощность/вес/габариты, загрузка нескольких изображений drag&drop + сортировка, PDF-паспорт, флаги «опубликовано» и «на главной» |
| **Категории** | Добавление, переименование, slug, описание, порядок |
| **Производители** | Название, страна, год основания, ссылка на сайт, описание, примечание |
| **Каталоги PDF** | Загрузка PDF и обложки, подписи (страницы, размер, год) |
| **Страницы** | Тексты всех страниц простыми полями (без конструктора) + SEO title/description |
| **Новости** | Создать, опубликовать/снять, удалить, привязать к карточке оборудования, дата, обложка |
| **Заявки** | Список, фильтр по статусу, комментарий менеджера, смена статуса (новая → в работе → закрыта), удаление, экспорт CSV (5000 строк, UTF-8 BOM для Excel) |
| **Пользователи** | Только администратор: создать, сменить роль, пароль, отключить доступ, удалить. Себя удалить нельзя |
| **Настройки** | Телефон, почта, адрес, часы, Telegram/WhatsApp, координаты, вариант логотипа, юридическая строка, четыре цифры статистики |

**Роли.** `admin` — всё. `editor` — контент и заявки, но не пользователи и не настройки.
Проверка роли выполняется **в каждом server action**, а не только в интерфейсе: прямой POST
без прав возвращает редирект, данные не меняются.

**Загрузка файлов.** `POST /api/admin/upload`: только авторизованные, лимит 12 МБ, проверка
не только MIME, но и сигнатуры файла (JPEG/PNG/WebP/AVIF/PDF). Имя генерируется случайным —
исходное имя не попадает на диск (защита от path traversal и подмены расширения).

## 10. Стек и архитектура

### Почему Next.js + SQLite, а не Strapi/Payload и не WordPress

| Вариант | Почему не выбран |
|---|---|
| **WordPress + ACF** | Знакомая админка, но каталог с фильтрами, сравнением и характеристиками пришлось бы собирать плагинами; производительность и безопасность требуют постоянного обслуживания. Для сайта на 12–50 позиций это оверинжиниринг с обратной стороны: много кода ради простых вещей. |
| **Next.js + Strapi/Payload** | Гибко, но это второй процесс, вторая база, второй деплой и вторая точка отказа. Заказчику нужна одна кнопка «сохранить», а не две админки и Docker Compose из четырёх сервисов. |
| **Next.js + SQLite (выбрано)** | Один процесс, одна база-файл, мгновенные запросы, простой бэкап копированием. Server actions дают формы без API-слоя. Каталог, фильтры и админка — ровно те, что нужны, без настройки CMS. |

Ограничение решения: один сервер и вертикальное масштабирование. Для 2–5 тысяч позиций и десятков
заявок в день этого достаточно с запасом. Если появится вторая площадка или потребуется горизонтальное
масштабирование, `lib/data.ts` — единственная точка доступа к данным: её можно переписать на Postgres/Prisma
без изменения страниц.

**Почему без Tailwind и Framer Motion.** Дизайн держится на токенах, чертёжных деталях и точных
состояниях — в utility-классах это превращается в кашу из `[&>*]:...`. Кастомный CSS на переменных
читается дизайнером и правится без сборки. Анимации — CSS + IntersectionObserver: 1,5 КБ вместо 40–60 КБ,
и полный контроль над `prefers-reduced-motion`.

### Структура

```
app/
├── (site)/            публичные страницы + layout (шапка, футер, compare-bar)
├── admin/             админка (отдельный layout, своя CSS)
├── api/admin/upload/  приём файлов
├── login/             вход
├── globals.css        токены, базовая типографика, кнопки, формы, теги
├── site.css           публичная часть (≈3,8 тыс. строк, секции по блокам)
├── sitemap.ts, robots.ts
components/            UI: шапка, футер, карточки, галерея, формы, сравнение, reveal, счётчики
lib/
├── db.ts              открытие SQLite + автосид
├── schema.ts          DDL
├── data.ts            все SELECT’ы
├── actions/           server actions (public.ts, admin.ts)
├── auth.ts            сессии, scrypt, роли
├── seo.ts, utils.ts, types.ts
└── seed*.ts           демо-контент
scripts/               генерация PDF и обложек
public/images/         фото (демо), public/docs/ — PDF, public/uploads/ — загрузки из админки
```

### Безопасность

- Пароли — `scrypt` с солью, сравнение через `timingSafeEqual`.
- Сессия — случайный 32-байтный токен в `httpOnly` cookie, `SameSite=Lax`, `Secure` в продакшене, TTL 14 дней.
- Все мутирующие server actions проверяют пользователя; действия с пользователями и настройками — только `admin`.
- Формы: honeypot-поле, проверка «человеческого» времени заполнения (<1,5 с = бот), rate limit 6 отправок
  за 10 минут на пару IP+телефон, валидация и нормализация телефона.
- SQL — только prepared statements, без склейки строк.
- Заголовки: `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`,
  CSP `frame-ancestors` (домены превью и self).
- Загрузка — проверка сигнатуры, лимит размера, случайные имена.

## 11. Развёртывание

### 11.1. Требования

- Ubuntu 22.04/24.04 (или Debian 12), Node.js **20.9+** (лучше 22 LTS).
- `build-essential`, `python3` — для сборки `better-sqlite3` (есть prebuilt-бинарники, но на чистом
  сервере надёжнее поставить инструменты).
- 1 ГБ RAM достаточно; сайт статически лёгкий, вся нагрузка — SQLite.

```bash
sudo apt update && sudo apt install -y build-essential python3 nginx certbot python3-certbot-nginx
# Node 22 через nodesource или nvm
```

### 11.2. Установка

```bash
git clone <repo> /var/www/vip-service && cd /var/www/vip-service
npm ci
cp .env.example .env
nano .env      # SITE_URL=https://vip-service23.ru, DATABASE_PATH=/var/lib/vip-service/vip-service.db
npm run build
```

Каталоги, которые обязаны пережить перезапуск и деплой:

| Путь | Что внутри |
|---|---|
| `/var/lib/vip-service/` | SQLite-база (`vip-service.db`, `-wal`, `-shm`) |
| `/var/www/vip-service/public/uploads/` | фото и PDF, загруженные из админки |

Создайте их заранее и выдайте права пользователю сервиса.

### 11.3. systemd

`/etc/systemd/system/vip-service.service`:

```ini
[Unit]
Description=Vip-service site
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/vip-service
EnvironmentFile=/var/www/vip-service/.env
ExecStart=/usr/bin/npm start
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now vip-service
```

### 11.4. nginx + HTTPS

```nginx
server {
  listen 80;
  server_name vip-service23.ru www.vip-service23.ru;
  client_max_body_size 15m;          # загрузка PDF до 12 МБ

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
```

```bash
sudo certbot --nginx -d vip-service23.ru -d www.vip-service23.ru
```

`client_max_body_size` обязателен: без него nginx отдаст 413 на загрузке каталога.

### 11.5. Обновление и бэкапы

```bash
# обновление
cd /var/www/vip-service && git pull && npm ci && npm run build && sudo systemctl restart vip-service

# бэкап базы (без остановки, корректно с WAL)
sqlite3 /var/lib/vip-service/vip-service.db ".backup '/backup/vip-$(date +%F).db'"
tar czf /backup/uploads-$(date +%F).tgz -C /var/www/vip-service/public uploads
```

Cron: бэкап раз в сутки, хранение 14 дней, отдельный диск или S3-совместимое хранилище.
Проверка восстановления — раз в квартал: развернуть копию базы на тестовом инстансе.

### 11.6. После первого запуска

1. Открыть `https://ваш-домен/login`, войти администратором.
2. **Сменить пароль** администратора и удалить/отключить демо-редактора.
3. Настройки → подставить реальные телефон, почту, адрес, часы, мессенджеры, координаты.
4. Заменить демо-цены и наличие на реальные.
5. Загрузить настоящие PDF-каталоги и обложки.
6. Проверить отправку заявки с телефона и получение её в админке.
7. Настроить бэкапы и только после этого запускать рекламу.

## 12. SEO, доступность, производительность

### SEO

- Уникальные `title` и `description` для каждой страницы, шаблон `%s · Vip-service` — только там,
  где бренда ещё нет (карточки оборудования и новости). Для страниц, у которых бренд уже в `seo_title`,
  используется `title.absolute`, чтобы не было «… · Vip-service · Vip-service».
- Open Graph и Twitter Card на всех страницах, OG-изображения 1200×630 генерируются скриптом.
- Микроразметка: `Organization` + `LocalBusiness` (адрес, часы, гео, услуги), `Product` + `Offer`
  (цена, наличие, состояние, характеристики), `BreadcrumbList` на карточках. Для позиций «по запросу»
  `Offer` не выводится — иначе Google ругается на Offer без цены.
- `sitemap.xml` генерируется из базы (включая все опубликованные станки и новости), `robots.txt`
  закрывает админку, API, логин и сравнение.
- Семантические заголовки: ровно один H1 на страницу, H2–H3 по секциям, осмысленные `alt` у всех фото.
- Canonical на каждой странице.

### Доступность

- Контраст: акцентный оранжевый на графите 5,63:1, мелкий акцент на бумаге — отдельный `#C23605` 4,53:1,
  вторичный текст 4,77:1. Плейсхолдеры не светлее основного вторичного текста.
- Видимый `:focus-visible` на всех интерактивных элементах (2 px контур акцента + отступ).
- Skip-link «Перейти к содержанию».
- Меню и мега-меню: `Esc`, focus-trap, возврат фокуса на кнопку, `aria-expanded`, `aria-current`.
- Формы: `<label>` связаны с полями, ошибки через `aria-invalid` и `aria-describedby`, статус отправки
  в `role="status"`.
- Все изображения с осмысленным `alt`; декоративные — `alt=""` и `aria-hidden`.
- `prefers-reduced-motion` уважается на уровне CSS и JS.

### Производительность

- Шрифты self-hosted, подключены через `@fontsource` с `font-display: swap`, только нужные начертания.
- Изображения — `next/image`: AVIF/WebP, адаптивные `sizes`, ленивая загрузка по умолчанию,
  `priority` только на hero.
- Ни одной внешней библиотеки анимаций, карт и слайдеров.
- Анимации только на compositor-friendly свойствах.
- Публичные страницы отдаются динамически (`force-dynamic`): склад и цены меняются из админки,
  и показывать покупателю закешированное «в наличии» через 10 минут — хуже, чем потратить лишние
  миллисекунды на рендер. При росте нагрузки включается ISR с `revalidatePath` на каждое сохранение —
  хуки уже расставлены в server actions.

**Целевые показатели Lighthouse:** Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95.
Замеры нужно сделать **на боевом домене после наполнения реальными фото** — в песочнице нет браузера,
а локальные замеры без CDN и сжатия nginx не показательны. Чек-лист ниже.

## Лицензия и передача

Код передаётся заказчику целиком, без внешних подписок и закрытых сервисов. Демо-изображения
сгенерированы для макета и подлежат замене на реальные фотографии; PDF-файлы — демонстрационные
выдержки, сгенерированные скриптом, а не официальные каталоги производителей.
